### 5.8 Vacancy source icons

`SourceIconsController` in module `source-icons/`, covered by the global Basic Auth like all of
`/api/*` (§6) — supplied by the browser for `<img>` within the same protection space.

#### `GET /api/vacancy-sources/:source/icon`

`:source` is a `VacancySource` value (§4.8: `HH`, `GETMATCH`, `IT_VACANCIES`, `GEEKJOB`) — per
**source**, not per record: every application and every vacancy lead of the same source shares one
cached file, unlike the per-record company logo (§4.10, §5.1, §5.7).

`200` — bytes with a whitelisted `Content-Type` (`image/x-icon` today, the same allow-list machinery
as the company logo), `Cache-Control: private, max-age=3600`, `X-Content-Type-Options: nosniff`.
`400` — `:source` is not a recognized `VacancySource`. `404` — the icon could not be downloaded, or
the cached file vanished from disk. `401` — without Basic Auth.

Bytes are fetched from the real site of the source (its own `favicon.ico`) through the shared
`logos/` cache (§4.10) — never proxied unauthenticated from the browser directly to hh.ru/getmatch.ru/
it-vacancies.ru/geekjob.ru. The download is lazy (first request only), deduplicated per source while
in flight, and negatively cached for an hour after a failure — see §4.10's final paragraph for the
full mechanics.

The frontend degrades to a coloured two-letter monogram badge when this endpoint answers `404`
(§7.2, §7.9).
