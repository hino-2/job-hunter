### 5.9 Resource `company-career-sites`

`CompanyCareerSitesController` in module `company-sites/`, covered by the global Basic Auth like all
of `/api/*` (§6). CRUD over the editable list backing the `COMPANY_SITE` lead-search source (§3.8,
§4.14) — the same «Сайты компаний» dialog opened from the «Вакансии» screen (§7.9.5).

| Method   | Path                            | Body                                | Success                      | Errors            |
| -------- | -------------------------------- | ------------------------------------ | ----------------------------- | ------------------ |
| `GET`    | `/api/company-career-sites`      | —                                    | `200` `CompanyCareerSiteDto[]`, ordered by `name ASC, id ASC` | `401` |
| `POST`   | `/api/company-career-sites`      | `{ name, url }`                      | `201` `CompanyCareerSiteDto`  | `400`, `401`       |
| `PATCH`  | `/api/company-career-sites/:id`  | `{ name?, url? }`                    | `200` `CompanyCareerSiteDto`  | `400`, `404`, `401`|
| `DELETE` | `/api/company-career-sites/:id`  | —                                    | `204`                         | `400`, `404`, `401`|

`CompanyCareerSiteDto`: `{ id, name, url, parserSupported, createdAt, updatedAt }`.

- `name` — trimmed, non-empty, ≤255 characters.
- `url` — trimmed, an absolute `http`/`https` URL (`require_protocol: true`, `require_tld: true` —
  stricter than `applications.vacancyUrl`'s `require_protocol: false`, §5.1: this address is read
  literally by the `hh-search` parser, §4.14, and must never be ambiguous about its scheme), ≤2048
  characters.
- `parserSupported` — `CompanySiteParserRegistry.resolve(url) !== null` (§4.14), computed by the
  controller on every response, never stored: it reflects the **current** set of implemented
  parsers, so it flips from `false` to `true` on its own once a matching parser ships (Stage 3, §4.14)
  without editing the row.
- `PATCH` body: absent field = untouched; explicit `null` on a non-nullable column = `400`; an empty
  body is a no-op that still answers `200` with the record as-is.
- Every `:id` goes through `ParseUUIDPipe` — a non-UUID value is `400`, not `404`.
- `404` message: «Сайт компании не найден».

No `GET /api/company-career-sites/:id` — the only client is the «Сайты компаний» table (§7.9), which
always renders the full list from the `GET` collection endpoint above; a single-record read has no
caller.
