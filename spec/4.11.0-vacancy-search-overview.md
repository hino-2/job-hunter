### 4.11 Vacancy search (hh.ru, it-vacancies.ru, geekjob.ru, company sites)

A pipeline separate from sync (§4.3): it does not update existing applications but **finds new vacancies**
into `vacancy_leads` (§3.5) for a separate tab (§7.9). Module `vacancy-search/`, dependencies
`VacancySearchModule → { HhModule, ItVacanciesModule, GeekjobModule, CompanySitesModule (§4.14),
VacancyAiModule, LogosModule, ApplicationsModule }`, no back-references.

**A run crawls one source or every lead-search source.** One run at a time process-wide (§4.11.9);
_which_ source(s) it crawls comes from the `POST /scan` body (§5.7). `source: 'ALL'` — the default
when the field is absent — visits every lead-search source in turn, one **leg** at a time, each leg
running the exact same source-agnostic pipeline described below; a concrete source visits just that
one leg. Everything source-specific is behind `VacancyLeadSearchProvider` (§4.8): the pipeline itself
— screening, dedup, budgets, stop/resume — is source-agnostic and exists exactly once, regardless of
how many legs a run has. Lead-search sources are `'HH'`, `'IT_VACANCIES'`, `'GEEKJOB'` and (§4.14, last
in the queue) `'COMPANY_SITE'`; `'GETMATCH'` is a sync-only source and is rejected with `400`, not
`500`. Deduplication, however, is source-**scoped** (§4.11.5): one leg never hides another leg's copy
of a cross-posted vacancy — the shared dedup key carries the source, so the same vacancy on two boards
produces two leads.
