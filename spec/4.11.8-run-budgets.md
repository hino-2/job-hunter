#### 4.11.8 Run budgets

| Limiter                        | Default    | Purpose                                                        |
| ------------------------------ | ---------- | -------------------------------------------------------------- |
| `VACANCY_SCAN_MAX_PAGES`       | `40`       | 2000 positions per run; equal to hh.ru's own ceiling (§4.11.1) |
| `VACANCY_SCAN_MAX_AGE_DAYS`    | `30`       | Freshness cutoff (§4.11.6)                                     |
| `VACANCY_SCAN_MAX_DURATION_MS` | `14400000` | Hard run deadline — 4 hours                                    |

Hitting a budget is not an error: the run reports `stoppedReason` and the next picks up the rest. One
vacancy's error does not abort a run (§4.6): a description failure is `descriptionsFailed`, an insert
failure is `failed`. Only an unparsable results page aborts a run (§4.11.3, fail-loud). The deadline is
dominated by the local model, not hh.ru — hh.ru requests at 2 rps take ≈ 20 s.

**Per-leg vs. per-run (§4.11.0).** `VACANCY_SCAN_MAX_PAGES` and `VACANCY_SCAN_MAX_AGE_DAYS` apply
**per leg** — each source in an `'ALL'` run pages from 0 up to its own `MAX_PAGES` limit and is judged
against the same freshness cutoff independently, so one source's depth or age exhaustion never shortens
another's. `VACANCY_SCAN_MAX_DURATION_MS` is the single run-wide budget: the deadline carries over from
leg to leg, and whichever leg first hits it ends the entire run, not just that leg.

**The deadline is sized for one full 40-page sweep.** Measured against live results: 6 pages took 30
minutes, so all 40 need roughly 3.5 hours, and the previous `1800000` default cut a run off around the
sixth page. A repeat run barely touches it — known vacancies are dropped by deduplication before any AI
(§4.11.5), so only genuinely new positions reach stage 3. A run that goes wrong no longer has to wait out
the deadline either: it can be stopped by hand (§4.11.12).

The per-run cap on opened vacancy pages (`VACANCY_SCAN_MAX_DETAILS`) was removed: the deadline above is
the only run-wide budget, so the number of vacancy pages a run may open is now bounded only by it, plus
the per-leg `VACANCY_SCAN_MAX_PAGES`/`VACANCY_SCAN_MAX_AGE_DAYS`.
