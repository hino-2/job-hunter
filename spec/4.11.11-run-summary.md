#### 4.11.11 Run summary

| Field                 | Meaning                                                                                                         |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| `pagesFetched`        | Results pages read                                                                                              |
| `pagesFailed`         | Results pages whose request or parse failed — skipped, the leg continues (§4.11.3)                              |
| `itemsSeen`           | Results items parsed                                                                                            |
| `skippedInvalid`      | Items missing required fields                                                                                   |
| `skippedOld`          | Cut off by `VACANCY_SCAN_MAX_AGE_DAYS`                                                                          |
| `skippedExcluded`     | Cut off by exclude keywords (stage 0 **title** or stage 3.5 **description**)                                    |
| `rejectedTitle`       | Model rejected by title (stage 1)                                                                               |
| `duplicates`          | Already in the DB or in this same run                                                                           |
| `descriptionsFailed`  | Description unavailable — vacancy not stored (§4.11.7)                                                          |
| `rejectedDescription` | Model rejected by description (stage 4)                                                                         |
| `created`             | Rows actually inserted                                                                                          |
| `failed`              | Insert errors                                                                                                   |
| `aiSkipped`           | Batches/vacancies dropped because the model's answer was unusable (§4.12.3)                                    |
| `stoppedReason`       | `COMPLETED` \| `LAST_PAGE` \| `MAX_PAGES` \| `DEADLINE` \| `AGE_LIMIT` \| `STOPPED` \| `AI_UNAVAILABLE` \| `ERROR` |
| `message`             | Explanation on `ERROR`, otherwise `null`                                                                        |

`GET …/scan/status` returns the same counters during a run — that is the progress display, alongside the
`pageProgress` indicator (§4.11.12): «page N of M». `STOPPED` (§4.11.12) is a user-requested stop, not a
failure — like every other non-`ERROR` reason it is still an operation result reported with HTTP `200`.
Since dedup now runs before the title AI (§4.11.4, §4.11.5), `duplicates` counts hits found either within
the run or already in the DB before the title model ever ran, and `rejectedTitle` counts only candidates
the model actually judged.

Stage 3.5 reuses `skippedExcluded` rather than introducing a new counter: §4.11.4's own description says
stage 0 is a cut by exclude keywords, and stage 3.5 is exactly the same deterministic cut, just over a
different text — `rejectedDescription` would be wrong (it means the *model* rejected the vacancy), and a
new counter would need changes to `VacancyScanProgress`, `ScanStatusDto`, the frontend mirror and this
table for no behavioural benefit.

**Multi-source runs (§4.11.0).** All counters above are **cumulative across legs** — a source: `'ALL'`
run keeps adding to the same `pagesFetched`/`pagesFailed`/`itemsSeen`/`created`/… totals as it moves
from one leg to the next, rather than resetting per leg; the model is warmed up (§4.11.9) exactly
**once** at the start of the whole run, not again for every leg. `stoppedReason`/`message` follow a
cross-leg rule: a failed results page (§4.11.3 — a request or parse failure) is skipped and counted in
`pagesFailed`, never `ERROR`; `ERROR` now comes only from an unexpected exception inside a leg, and
such an exception does **not** cancel the legs still to come — the error is remembered and the run moves
on to the next source, and the eventual `stoppedReason` is `ERROR` with `message` a `'; '`-joined list
of `'<SOURCE>: <text>'` entries, one per failed leg (the `'<SOURCE>: '` prefix is added only when the
run has more than one leg). `STOPPED`, `DEADLINE` and `AI_UNAVAILABLE`, by contrast, end the **whole**
run at whichever leg they are hit on, exactly like a single-source run. A leg whose own results are
simply exhausted (`COMPLETED`, `LAST_PAGE`, `MAX_PAGES`, `AGE_LIMIT`) contributes nothing to
`stoppedReason`/`message` beyond becoming the run's current answer until a later leg overrides it, and
the run moves on to the next source.
