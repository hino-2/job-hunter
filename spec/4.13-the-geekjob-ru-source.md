### 4.13 The geekjob.ru source

The fourth source, and — unlike getmatch.ru — implements **both** contracts of §4.8: sync
(`VacancySourceProvider`) and lead search (`VacancyLeadSearchProvider`), the same shape as
it-vacancies.ru.

**Vacancy page.** Server-rendered HTML, no JS needed: `GET {GEEKJOB_SITE_BASE_URL}/vacancy/{24-hex id}`
(no trailing slash — unlike it-vacancies.ru, a slash is not required and omitting it saves a throttle
slot on a redirect). A short-link form also exists (`geekjob.ru/{6-char-slug}`, rendered inside the page
as `div.short-link[data-href]`) but is **not** recognized by the URL parser — resolving it would need an
extra network request, and a pasted short link yields `SKIPPED_UNSUPPORTED` (§4.5), a documented
limitation, not a bug.

| Field        | Selector                                                              | Notes                                                                             |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| title        | first (and only) `<h1>` on the page                                    | Absent/empty → fail-loud `null` (`ERROR`) — the only "this really is a vacancy page" signal |
| company name | `<h5 class="… company-name …">` → its **first** `<a>`                  | The **second** `<a>` of the same block (`id="company-web"`) is the company's own site, not its name |
| company logo | `#logo-box figure[style]` → `background-image:url('…')`                | **Never** match by the class `company-list-logo` — that class belongs to the "similar vacancies" sidebar cards, i.e. *other* companies' logos |
| description  | `#vacancy-description` inner HTML                                      | Delimited by the same `<div>`-depth pass as it-vacancies.ru (promoted to `common/html.helpers.ts`, `extractBalancedDivBlock`) |

A nonexistent/removed vacancy answers **HTTP 404** (verified live) → `NOT_FOUND`, exactly like
it-vacancies.ru — unlike getmatch.ru, where the parser derives `NOT_FOUND` from the page content.

**`archived` is always `false` — NOT VERIFIED as a marker, but the 404 behavior above is confirmed
live.** An old (2022) vacancy that is presumably no longer being hired for still answers `200` with
**no** archive marker of any kind (checked for `архив`/`закрыт`/`снят` — zero hits) and still renders
the «Откликнуться» button. `GEEKJOB_ARCHIVED_MARKER_PATTERN` ships as a documented heuristic — the same
shape as `IT_VACANCIES_ARCHIVED_MARKER_PATTERN` — that has never matched a live page. The only reliable
archived signal for geekjob.ru is `log.archived` in the search JSON below, and it exists **only** in the
paginated results, not per-id — so it cannot serve the sync lane, and an archived-but-still-served
geekjob vacancy will never be derived to `VACANCY_WITHDRAWN` from its own page.

**Search results.** The user-facing search page (`/vacancies?…`) is client-rendered by Vue and its
`ul#serplist` is empty on the raw HTML — unusable. Results actually come from an internal JSON endpoint:

```
GET {GEEKJOB_SITE_BASE_URL}/json/find/vacancy?page=<n>&<same query params as the search page>
```

The settings template (`geekjob_search_url_template`, §3.6) stays the **user-facing** URL
(`.../vacancies?rm=1&qs=node&page={page}`) so the UX matches hh.ru/it-vacancies.ru — `buildGeekjobSearchUrl`
substitutes `{page}` (source pages are 1-based, the run loop is 0-based, same rule as it-vacancies.ru)
and then **rewrites `url.pathname`** to `/json/find/vacancy`, keeping the query string as-is. The origin
check (`https://` + a geekjob.ru host) runs on the **raw** template, before either substitution — the
same SSRF safeguard as the other two search-URL helpers.

**Response body may already be an object.** The shared axios options (`vacancy-http-options.factory.ts`)
set `responseType: 'text'` and rely on axios's default `transformResponse` failing to `JSON.parse` an
HTML page — that assumption does **not** hold for this JSON endpoint: axios successfully parses it into
an object before the parser ever sees it. `parseGeekjobSearchPage`/`countGeekjobSearchSignals` therefore
coerce the payload explicitly: a `string` is `JSON.parse`d in a `try/catch`, anything else (already an
object) is used as-is. This was the single most likely implementation bug and is covered by both shapes.

```json
{
  "page": 1, "nextpage": 0, "pagecount": 1, "documentsCount": 15,
  "data": [{
    "id": "6a852ae8d9c7be6371007feb",
    "position": "Junior FullStack Developer",
    "salary": "100K — 180K ₽",
    "country": "Россия", "city": "Москва",
    "jobFormat": { "remote": true, "relocate": false, "parttime": false, "inhouse": false },
    "log": { "modify": "19 августа", "archived": null },
    "company": { "type": 1, "name": "Sasha AI", "logo": "260818085839.png", "id": "6a83f44ed600d4ec2605f910" },
    "sortOrder": "20260819"
  }]
}
```

| JSON field                        | Destination                        | Requirement                                                    |
| ---------------------------------- | ----------------------------------- | ---------------------------------------------------------------- |
| `id` (24-hex)                      | `external_id`, `vacancy_url`        | required, else item skipped (`skippedInvalid`)                  |
| `position`                         | `position`                          | required (non-empty)                                             |
| `company.name`                     | `company`                           | required (non-empty)                                             |
| `sortOrder` (`YYYYMMDD`)           | `published_at` / `published_on`     | required — see below                                              |
| `city` / `country`                 | `area_name`                         | `city` if non-empty, else `country`, else `null`                 |
| `salary` (short form)              | `salary_from`/`salary_to`/`salary_currency` | soft-degrades to `null`; see grammar below                |
| `jobFormat.{remote,inhouse,parttime,relocate}` | `work_formats` (comma-separated) | soft-degrades to `null`                                    |
| `log.archived`                     | (not stored)                        | non-`null` → item skipped as `skippedInvalid`, never inserted    |

- **`sortOrder`, not `log.modify`, is the publication date.** `sortOrder` is an unambiguous `YYYYMMDD`
  string present on every item and is the source's own freshness key.  `log.modify` is a Russian
  day+month string with the year omitted for the current year, and disagrees with `sortOrder` on
  observed samples (e.g. `"9 декабря 2025"` vs. `sortOrder: "20260907"`). Using `sortOrder` removes the
  need for a Russian month-name parser (none exists in the codebase) and matches the day-start instant
  `{Y}-{M}-{D}T00:00:00+03:00` — the `+03:00` offset is **NOT VERIFIED**, same status as
  `IT_VACANCIES_TIME_ZONE_OFFSET`. `sortOrder` is a re-bump date, not the original publication date, so
  a re-bumped vacancy yields a new dedup key — the same semantics §4.11.5 already accepts for
  re-publications.
- **An archived item (`log.archived != null`) is counted into `skippedInvalid`**, not into `items` — it
  is dropped from the run the same way a structurally-invalid item is, since `log.archived` is the only
  place this source ever exposes an archived signal.
- `pagecount` (a positive integer, or a numeric string) → `lastPage = pagecount - 1` (0-based, like the
  rest of the loop); a non-positive/non-numeric value → `lastPage = null` and the run relies on the page
  budget and an empty page, same fallback as it-vacancies.ru.
- Salary short-form grammar (differs from the full form on the vacancy page, which is **not** parsed —
  §12 forbids reading salary off a vacancy page): `"100K — 180K ₽"` (range), `"от 800 €"` /
  `"до 150K ₽"` (open-ended), `"27.2K ₽"` (a single bare number — the **exact** salary, `from = to`),
  `""` (not stated → all three fields `null`). Currency comes from the first of `₽`/`$`/`€` found in the
  string.
- No date-sort field exists in the default template (geekjob.ru's own default order is relevance, not
  date) — the §4.11.6 early stop by age effectively never fires for the default query; a run ends on
  `COMPLETED`/`LAST_PAGE`/`MAX_PAGES` instead. A `sort=` parameter exists in the site's own search form
  but its accepted values were not verified and nothing is built around it.

**Verified live (18.09.2026):** vacancy page — `200`, plain HTML, ordinary browser `User-Agent` works,
no cookies/auth needed. Search JSON endpoint — `200`, no auth, no special header required. A nonexistent
vacancy id → `404`. `/json/find/vacancy?page=1&rm=1&qs=node` sample: 15 documents, 1 archived
(`log.archived` non-null, from 2022) → 14 valid items, `pagecount: 1` → `lastPage: 0`.

`GEEKJOB_USER_AGENT` is optional with a safe default (`job-hunter/1.0`), like `GETMATCH_USER_AGENT` and
`IT_VACANCIES_USER_AGENT` — no source-specific User-Agent requirement was found. Its own throttle,
`GeekjobRequestThrottle`/`GEEKJOB_MAX_REQUESTS_PER_SECOND` (default `2`), is shared by sync and search
inside `GeekjobModule`, the same one-instance-per-source rule as the other two throttled sources
(§4.11.2).
